Bada server ya aur servers?

Vertical vs horizontal scaling: kab kaunsa chahiye, aur galat choice pe paisa kaise jalta hai. Interview answer sabse pehle, phir samjhaata hoon.

Interview mein ye bolo

  1. App servers stateless rakho aur load balancer ke peeche scale out karo.
  2. Database ko jab tak ho sake scale up karo, kyunki database ko todna mushkil hai.
  3. Reads zyada hon toh read replica jodo. Writes phir bhi ek primary pe jaate hain.
  4. Sharding sabse aakhir mein, jab writes ya data sabse badi machine se bhi bada ho jaaye.
  5. Size naap ke chuno, andaaze se nahi. Asli usage dekho, phir machine chuno.

Photocopy dukaan se samjho

  • Ek photocopy machine=server
  • Purani machine ki jagah tez machine=vertical / scale up
  • Teen machines rakh lo=horizontal / scale out
  • Counter wala jo print khaali machine ko bheje=load balancer
  • PDF sirf machine 1 ke desktop pe=local state
  • Dukaan ki shared drive=shared store
  • Akeli machine atki, dukaan band=single point of failure

25 minute ka task: session kahan rakhoge?

Do chhote server, ek load balancer. Pehle login RAM mein rakhenge aur dekhenge kya toot-ta hai. Phir shared store mein rakh ke theek karenge. Sirf Python chahiye, koi library nahi (Locust optional).

  1. Teeno files ek folder mein save karo.
  2. Teen terminal kholo aur chalao: python app.py 8001, python app.py 8002, python lb.py
  3. Browser mein kholo: 127.0.0.1:8000/login?user=riya. Jo token mile, usse 127.0.0.1:8000/me?token=TOKEN kholo aur 5-6 baar refresh karo.
  4. Dono app servers band karo aur shared ke saath dobara chalao: python app.py 8001 shared, python app.py 8002 shared. Step 3 dobara karo.
  5. Optional: pip install locust, phir locust -f locustfile.py --headless -u 10 -r 2 -t 30s -H http://127.0.0.1:8000 aur failures dekho.

Kaam kiya toh: RAM mode mein har doosra refresh kaun? login karo dikhayega, kyunki login doosre server ki RAM mein tha. Shared mode mein har refresh hello riya, bas server number badalta rahega. Yahi stateless server hai.

app.py 
import sys, uuid, sqlite3
from http.server import ThreadingHTTPServer, BaseHTTPRequestHandler
from urllib.parse import urlparse, parse_qs

PORT = int(sys.argv[1])
SHARED = len(sys.argv) > 2 and sys.argv[2] == "shared"
memory = {}  # token -> user. Sirf isi process ki RAM mein.

def db():
    c = sqlite3.connect("sessions.db", timeout=5)
    c.execute("CREATE TABLE IF NOT EXISTS s (token TEXT PRIMARY KEY, user TEXT)")
    return c

def save(token, user):
    if SHARED:
        c = db(); c.execute("INSERT INTO s VALUES (?, ?)", (token, user)); c.commit(); c.close()
    else:
        memory[token] = user

def load(token):
    if SHARED:
        c = db(); row = c.execute("SELECT user FROM s WHERE token = ?", (token,)).fetchone(); c.close()
        return row[0] if row else None
    return memory.get(token)

class H(BaseHTTPRequestHandler):
    def do_GET(self):
        url = urlparse(self.path)
        q = parse_qs(url.query)
        if url.path == "/login":
            token = uuid.uuid4().hex[:8]
            save(token, q.get("user", ["guest"])[0])
            self.reply(200, f"token={token}")
        elif url.path == "/me":
            user = load(q.get("token", [""])[0])
            if user:
                self.reply(200, f"hello {user}")
            else:
                self.reply(401, "kaun? login karo")
        else:
            self.reply(404, "nahi mila")

    def reply(self, code, text):
        body = f"{text}  (server {PORT})\n".encode()
        self.send_response(code)
        self.send_header("Content-Type", "text/plain")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass

if SHARED:
    db().close()  # table pehle se bana lo
print(f"server {PORT} chalu, store = {'sqlite (shared)' if SHARED else 'RAM'}")
ThreadingHTTPServer(("127.0.0.1", PORT), H).serve_forever()
lb.py 
import itertools, http.client
from http.server import ThreadingHTTPServer, BaseHTTPRequestHandler

BACKENDS = itertools.cycle([("127.0.0.1", 8001), ("127.0.0.1", 8002)])

class LB(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/favicon.ico":       # browser ki extra request, round-robin na bigde
            self.send_response(404); self.send_header("Content-Length", "0"); self.end_headers()
            return
        host, port = next(BACKENDS)
        try:
            conn = http.client.HTTPConnection(host, port, timeout=5)
            conn.request("GET", self.path)
            r = conn.getresponse()
            code, body = r.status, r.read()
            conn.close()
        except OSError:
            code, body = 502, f"server {port} band hai\n".encode()
        self.send_response(code)
        self.send_header("Content-Type", "text/plain")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass

print("load balancer: http://127.0.0.1:8000")
ThreadingHTTPServer(("127.0.0.1", 8000), LB).serve_forever()
locustfile.py (optional) 
from locust import HttpUser, task, between

class Student(HttpUser):
    wait_time = between(0.5, 1)

    def on_start(self):
        r = self.client.get("/login?user=riya")
        self.token = r.text.split()[0].split("=")[1]   # "token=ab12cd34  (server 8001)"

    @task
    def me(self):
        self.client.get(f"/me?token={self.token}", name="/me")

Ek screen ki cheat sheet

Vertical (scale up)
Wahi app, badi machine. Code same, par upgrade pe thoda downtime, aur sabse badi machine ke baad aage raasta nahi.
Horizontal (scale out)
Zyada machines, load balancer ke peeche. Tabhi chalega jab koi bhi server koi bhi request sambhal sake.
Load balancer
Har request kisi free server ko bhejta hai. Akela ho toh khud single point of failure ban jaata hai.
Stateless
Server apni RAM ya disk mein user ki koi baat nahi rakhta. Session, uploads aur cache bahar rehte hain.
Shared store
Sessions ke liye Redis ya database, files ke liye object storage (S3 jaisa).
Read replica
Database ki read-only copy. Reads baant deta hai, writes phir bhi ek primary pe.
Sharding
Data tukdon mein, har tukda alag database pe. Writes scale hote hain, par joins aur rebalancing mushkil. Isliye sabse aakhir mein.
Autoscaling
Traffic dekh ke servers khud badhte-ghatte hain, toh peak ka paisa sirf peak ke time lagta hai.
